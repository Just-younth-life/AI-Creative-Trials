# 汪独 · Bad Case 记录

> 记录对象：玩家/查看者在体验《汪独：脑力益智游戏》各版本过程中遇到的异常现象。
> 记录口径：仅描述「看到什么、怎么触发、对体验的影响」。本次新增问题附一句原因说明。
> 本文件不含修复方案与改进逻辑。

---

## BC-001（本次新增）放满第一关全部 4 只西高地后，停留在原关不进入下一关

- **现象**：第一关（4×4）在棋盘上放好 4 只西高地后，界面没有弹出通关画面，也没有进入第 2 关，玩家仍停在本关棋盘上，会误以为"放对了却没反应 / 卡住了"。
- **触发步骤**：进入游戏 → 点第 1 关 → 依次点击 4 个空白格放下西高地 → 观察界面。
- **用户影响**：完成感缺失，玩家反复点击棋盘或重开，怀疑自己是否放对、怀疑游戏是否出错；新玩家可能因此流失在引导关。
- **原因说明（本次）**：当前只有在玩家主动点击「检查答案」按钮时才会触发通关判定，放满最后一只西高地时不会自动完成，因此棋盘填满后界面不会跳转。

## 此前已出现并反馈过的体验问题

### BC-002 每个格子显示的是"一整张 6 只西高地"的图，看不清到底放了几只
- **现象**：棋盘格子里出现的不是单只西高地，而是一张包含 6 只狗的整图缩略图，视觉混乱。
- **触发步骤**：进入任意关卡 → 放置西高地 → 观察格内图案。
- **用户影响**：玩家无法直观判断"这一格是 1 只还是 6 只"，也无法辨认放了几只，破坏解谜的可读性。

### BC-003 棋盘色区颜色太浅，格子边界看不清
- **现象**：各彩色区域的填充色与格子边缘对比不足，相邻格子糊在一起。
- **触发步骤**：进入关卡 → 观察棋盘。
- **用户影响**：难以分辨色区范围，直接妨碍"每个色区恰好一只"的规则判断，增加无谓的视觉负担。

### BC-004 放错位置后，错误标记一闪就消失，无法追溯错过哪里
- **现象**：点错格子时红叉短暂闪现后不见了，玩家回头找不到自己错过的位置。
- **触发步骤**：在关卡中点一个错误格子 → 等待片刻 → 回看棋盘。
- **用户影响**：玩家无法从错误中学习，重复踩同一个坑，挫败感累积。

### BC-005 扣大骨棒时反馈很弱，玩家不容易察觉"掉血"
- **现象**：放错后生命值减少，但缺少明显的扣减提示，注意力不在血条上时几乎无感。
- **触发步骤**：连续点错格子 → 观察生命值区域。
- **用户影响**：玩家不知道还剩几次机会，直到突然失败才意识到，体验突兀。

### BC-006 爪印排除标记视觉弱，和普通标记分不清
- **现象**：用于"标记此格不放"的爪印/叉号样式不明显，与已放置的西高地或其他状态容易混淆。
- **触发步骤**：切换到排除工具 → 在格子上做标记 → 观察。
- **用户影响**：推理线索表达不清，玩家怀疑标记是否生效，影响解题节奏。

### BC-007 所有关卡一开始全部开放，缺少解锁与成长感
- **现象**：首次进入游戏即可点击任意关卡，没有"先过前一关"的限制。
- **触发步骤**：首次打开游戏 → 查看关卡列表。
- **用户影响**：缺少循序渐进的目标感，新手可能直接跳到高难关卡被劝退。

### BC-008 首页封面用一整张大插画当图标，图标过大、挤压标题文字
- **现象**：首页顶部是一张占满宽度的大插画，"汪独"标题与副标题被压在图上，视觉拥挤。
- **触发步骤**：打开游戏首页 → 观察顶部区域。
- **用户影响**：标题信息被画面干扰，第一眼抓不住重点，整体显得笨重。

### BC-009 题库导入后一度出现 0 关，玩家无关卡可玩
- **现象**：某个版本进入游戏后关卡列表为空，无法开始任何一关。
- **触发步骤**：打开对应版本游戏 → 查看关卡列表。
- **用户影响**：玩家完全无法游玩，属于阻断级问题。

### BC-010 装饰图标用系统表情符号，风格与整体画面不统一
- **现象**：工具栏与弹窗图标是系统自带的表情符号，和精致的西高地主题画面风格不一致，显得粗糙。
- **触发步骤**：进入关卡 → 观察工具栏；通关 → 观察弹窗。
- **用户影响**：画面质感被拉低，破坏沉浸感，与"精细化"的视觉预期不符。

### BC-011 源码文件（.py）在预览面板无法直接打开查看
- **现象**：点击 `import_bank.py` 后预览面板不显示可读内容，查看者看不到里面是什么。
- **触发步骤**：在文件预览中点击 `.py` 文件。
- **用户影响**：查看者误以为文件损坏或内容丢失，无法确认交付物是否完整。

### BC-012 查看者误以为 `.py` 文件打开后就是可玩的游戏
- **现象**：点击 `import_bank.py` 期待看到游戏，结果看不到任何画面，产生"这不是我要的东西"的落差。
- **触发步骤**：收到交付文件 → 点击 `.py` 文件 → 期待出现游戏。
- **用户影响**：查看者困惑、反复确认，增加沟通成本，不清楚真正可玩的是哪个文件。

### BC-013 点击「骨头雷达」工具后没有任何可见反应
- **现象**：进入关卡后点击工具栏的「骨头雷达」，界面无变化、无提示、无次数扣减，玩家以为按钮坏了。
- **触发步骤**：进入关卡 → 点击工具栏「骨头雷达」卡片 → 等待反馈。
- **用户影响**：玩家无法获得任何探测提示，道具形同虚设；反复点击后产生"游戏有 bug"的直接印象，损害对整体品质的信任。

### BC-014 放错两只狗后全盘被排除，玩家不知道还能继续（软死锁无引导）
- **现象**：合法放置两只西高地后（位置不违规但不在解上），棋盘所有剩余格子显示「不可放」✕，玩家以为游戏卡死，不知道接下来怎么办。
- **触发步骤**：进入 4×4 关卡 → 放两只合法但错位的西高地 → 观察棋盘。
- **用户影响**：数独类玩法的核心认知门槛——玩家不知道「点击已放的西高地可以拿起重新安置」，产生"这游戏没法玩了"的误解，甚至直接放弃。

## 本次（11/23 晚）修正的问题

### BC-015 点击已放西高地可无限撤回，靠反复试错就能过关
- **现象**：放下一只西高地后点它即可拿回，且没有次数限制；玩家可以反复"放上—看排除范围—拿回—换位置"，靠穷举把答案筛出来。
- **触发步骤**：进入任意关卡 → 放下一只 → 反复点击该格拿起/放下 → 观察排除范围变化。
- **用户影响**：谜题从"推理"退化为"试错"，挑战感与成就感消失，玩家会觉得"这游戏不用动脑"。
- **原因说明（本次）**：撤回逻辑只做了"拿起"，未与次数/成本挂钩；且重开也无限，形成完整的试错闭环。

### BC-016 「Clear（清除标记）」与「↻ 重开」功能边界模糊，玩家分不清
- **现象**：两个按钮都会让棋盘上的内容消失，玩家难以判断该点哪个；点 Clear 后骨棒没恢复、红叉还在，与预期不符。
- **触发步骤**：进入关卡 → 放下几只西高地并故意放错一次 → 分别点击左下 Clear 与右上 ↻ → 对比结果。
- **用户影响**：误用高代价的重开、或误以为 Clear 能恢复资源，产生"这游戏逻辑混乱"的判断。
- **原因说明（本次）**：两者职责不同（Clear 只清狗与爪印、不恢复骨棒、不占重开配额；重开整关重置），但 UI 上没有任何区分提示。

### BC-017 通关弹窗把用时/骨棒/失误/奖励挤成一行小字，一眼看不到重点
- **现象**：Level Clear 弹窗中信息连成一行（Time … · bones left … · mistakes … / Rewards … / Next level unlocked），字号偏小、层级相同。
- **触发步骤**：任意关卡通关 → 观察弹窗正文。
- **用户影响**：玩家无法快速判断"这局打得怎么样、拿到了什么"，通关的正反馈被稀释。
- **原因说明（本次）**：结算内容以单段纯文本输出，没有做信息分组与颜色分级。

### BC-018 通关后没有任何评级，玩家不知道这局算好还是差
- **现象**：通关只显示用时和剩余骨棒，没有星级或其他评价维度，重玩缺少目标。
- **触发步骤**：任意关卡通关 → 观察结算与关卡页。
- **用户影响**：缺少"再打一次拿三星"的轻量留存动力，关卡列表也没有可视化的完成质量。
- **原因说明（本次）**：初版只做通关/失败二元判定，未设计评价维度。

### BC-019 首页试玩视频区域显示为空白，看不到视频
- **现象**：视频文件确实存在且能播放，但页面初始只显示占位提示，需等待脚本事件触发后才出现播放器；部分环境下事件未触发，访客看到的是空白框。
- **触发步骤**：打开 index.html → 滚动到「05 试玩视频」→ 观察该区域。
- **用户影响**：最直观的展示位看起来"没做"，直接影响访客对完成度的判断。
- **原因说明（本次）**：播放器默认 display:none，依赖 loadeddata 事件再显示；在事件未触发的环境中永久隐藏。

### BC-020 首页大骨棒背景旋转后撑破容器，页面出现横向滚动条
- **现象**：首页右侧大骨棒图片旋转 -45° 后的外接矩形远宽于容器，桌面宽度下页面可左右拖动，出现横向滚动。
- **触发步骤**：宽屏（≥1200px）打开 index.html → 尝试左右拖动页面。
- **用户影响**：页面"跑偏"的观感，滚动条暴露实现粗糙，移动端也会被误触拖动。
- **原因说明（本次）**：旋转元素未做父级裁切，且旋转后 bounding box 计算未纳入布局。

### BC-021 Hero 区六只西高地被裁成六个小方块，手写角色名被切掉
- **现象**：插画按 2×3 网格裁切成小卡片后，狗旁边的 SHU PIAN DOG 等手写名字只剩一半或完全消失。
- **触发步骤**：打开 index.html 首屏 → 观察右侧六只狗的图卡。
- **用户影响**：插画的叙事细节丢失，视觉上像"低分辨率缩略图堆叠"。
- **原因说明（本次）**：为追求列式排布使用了雪碧图裁切，未考虑原图的文字留白区域。

### BC-022 删除一个模块后章节编号从 01b 跳到 03，出现跳号
- **现象**：页面章节依次为 00、01、01b、03、04…，中间缺失 02，访客会以为内容漏了一节。
- **触发步骤**：滚动浏览 index.html 各区块小标题。
- **用户影响**：信息架构显得不严谨，降低作品集的专业印象。
- **原因说明（本次）**：删除模块后未同步重排编号。

### BC-023 游戏视觉区新增第 4 屏后，四屏高度明显不齐
- **现象**：四台手机框中首页屏高度明显高于其他三屏（376px vs 272–286px），底部对齐时顶部参差突出。
- **触发步骤**：打开 index.html → 滚动到「00 游戏视觉」三联屏区域。
- **用户影响**：视觉上像"没对齐的拼贴"，削弱产品展示的精致感。
- **原因说明（本次）**：新增屏使用等比原图，未与其他屏统一内容高度。

### BC-024 关卡数据引用被改坏后，页面看似正常但全部关卡消失（静默失败）
- **现象**：打开 game.html，封面标题、每日谜题卡、三张路径卡都正常显示，但「Adventure Paths」下方的关卡节点一个都不出现，点击路径卡也没有任何关卡可点，游戏完全无法开始；页面本身不弹任何错误提示。
- **触发步骤**：打开 game.html → 观察路径卡下方的关卡节点区 → 点击任一路径卡 → 进入开发者工具查看控制台。
- **用户影响**：核心玩法入口整体消失，Demo 退化成"只有封面的静态页"；又因为封面、按钮、路径卡都在，访客不会判断为"坏了"，只会认为"这个作品没做完"，问题几乎不会被反馈上来。
- **原因说明（本次）**：关卡数据原本由 `<script src="levels.js"></script>` 引入，版本编辑过程中这一行被写成了 `<script src=></script>` 和 `<script>“level.js"`（弯引号），游戏主脚本块首行即语法错误，整段逻辑未执行，`WANGDU_DATA` 始终未定义；代码里 `typeof WANGDU_DATA!=='undefined' ? WANGDU_DATA : {levels:[]}` 的兜底又把"数据缺失"静默降级为"0 个关卡"，所以界面照常渲染、表面无异常。
